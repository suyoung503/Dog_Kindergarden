# 맡겨멍 — 기능 명세

이 문서만 읽어도 앱에 어떤 기능이 있는지 알 수 있도록 정리한 기능 카탈로그다.
기술적 설계 배경은 `PORTFOLIO.md`, 배포 현황은 `DEPLOYMENT_REMAINING.md`를 참고한다.

**맡겨멍**은 반려견을 맡길 수 있는 서울의 애견 유치원·호텔을 지도에서 탐색하고,
찜·리뷰·채팅·예약까지 한 앱에서 해결하는 iOS 플랫폼이다.
가게 기본 데이터는 공공데이터와 운영 검수 결과를 D1에 저장해 제공하고,
예약·채팅·리뷰·찜 등 사용자 데이터는 자체 백엔드(Cloudflare Workers + D1)에 저장한다.

**마지막 업데이트:** 2026-10-27

실기기 수정안의 WebSocket·반려견 R2 사진·공유 링크·보유기간 서버 변경은 2026-10-26 운영 배포했고, 2026-10-27 초기 알림 복구·커서 경계를 보완했고, 2026-10-28 프로필 동기화·실시간 알림·예약별 사진 API에 이어 예약 당시 정보 저장·예약 상세 API·가게 신청 거절 알림도 운영 DB와 함께 반영했다. 최신 iOS 앱 설치 후 실기기 검증은 별도이며, 버전과 확인 범위는 `DEPLOYMENT_REMAINING.md`를 따른다.

## 1. 계정 · 로그인

### 카카오 간편로그인
- 시작 화면에서 **역할(보호자 / 보호자·사장님)을 선택**한 뒤 카카오 로그인.
- 처음이면 자동 회원가입(`POST /api/auth/kakao`), 서버에 저장된 연락처·주소·이메일이 있으면 로컬 프로필(`UserProfile`)에 동기화.
- 로그인 창을 사용자가 직접 닫으면(취소) 에러 문구를 띄우지 않는다.

### 역할은 계정에 영구 귀속
- 최초 가입 시 선택한 역할이 카카오 계정에 묶인다(서버 `users.is_owner`).
- 같은 계정으로 **반대 역할 가입 시도는 서버가 409로 거절**하고, 앱이 "이미 ○○ 계정으로 가입된 카카오 계정이에요" 안내를 띄운다.
- 목적: 견주와 사장님이 채팅·찜·예약·최근 본 가게 데이터를 섞이지 않게 완전 분리. 잘못 가입한 역할은 앱의 회원 탈퇴 후 새 계정으로 다시 가입할 수 있다.
- 역할에 따라 화면을 분기하지 않는다. 로그인 후 목적지는 항상 홈이고, 사장님 여부는 사이드바의 '받은 예약 요청' 노출과 마이페이지 '내 가게' 항목 등 **기능 단위로만** 달라진다.

### 개발자 진입 (시뮬레이터용)
- `#if DEBUG`와 로컬 API에서만 노출되는 우회 로그인. 운영 Worker는 `/api/auth/dev`를 `404`로 차단하고 Release 실행 파일에는 개발자 진입 문구가 포함되지 않는다.

### 로그아웃
- 마이페이지에서 확인 알림 후 로그아웃. 내비게이션 스택을 시작 화면으로 통째로 교체하고, 선택 상태·최근 본 가게 등 세션 데이터를 전부 비워 계정 간 잔존 데이터를 막는다.

## 2. 홈 · 지도 탐색

### 서울 가게 지도
- 현재 운영 D1에 선별한 서울의 위탁관리업체(유치원·호텔)를 불러온다.
- 좌표가 TM(EPSG:5181)이라 자체 구현한 `TMConverter`로 WGS84 위경도로 변환(대한민국 범위 밖 좌표는 필터링).
- 마스킹된 주소는 **카카오 로컬 API**로 보강.
- 가게 유형 아이콘은 공통 `storeTypeEmoji(_:)` 규칙을 사용한다. 호텔은 `emoji_hotel`, 유치원은 `kindergarden`, 혼합·미분류는 어느 한쪽으로 단정하지 않고 `icon_paw`를 표시한다.

### 뷰포트 기반 핀 표시
- 지도 이동이 멈추면 현재 화면에 보이는 위경도 범위 안의 가게만 핀으로 표시(도 경계 무관), 중심에서 가까운 순으로 개수 상한. 초기 화면은 수도권 뷰.

- 상세 화면에서 돌아와도 지도 위치·확대·회전·기울기와 검색/필터를 유지한다. 계정 전환 시 지도 상태를 초기화한다.

### 최근 본 가게
- 핀을 눌러 확인한 가게가 홈 하단 '최근 본 케어' 목록에 쌓인다. 사진이 없는 카드의 호텔·유치원 기본 이미지는 중앙에 크게 표시하고, 유형 배지는 별도로 유지한다.
- **계정별로 영구 저장**(UserDefaults `recent_pins_<userId>`) — 재로그인해도 유지되고, 최신순 최대 6개(넘치면 오래된 것부터 삭제), 견주/사장님 계정이 각자의 목록을 가진다.

### 사이드바(FAB)
- 홈 우하단 발자국 버튼: 강아지 프로필 / 채팅 / 예약 내역 / 설정(마이페이지).
- 사장님 계정에만 **받은 예약 요청** 항목이 추가로 노출된다.

### 종 아이콘 — 앱 내부 알림함
- 홈 우상단 종 아이콘은 계정별 알림함으로 이동한다. 읽지 않은 이벤트가 있으면 빨간 점을 표시하고, 항목을 누르면 채팅·예약·고객센터·가게 등록 요청 화면으로 이동한다.
- 시스템 알림 권한을 거부해도 앱 사용 중 조회한 이벤트는 알림함에서 확인할 수 있다.

### 알림 피드 — 포그라운드 WebSocket + 영속 피드
- 앱 사용 중 `GET /api/realtime`에 Bearer 인증 WebSocket을 연결한다. 예약·채팅·알림장·신규 가게 등록 신청·신청 거절·문의 변경 이벤트를 받으면 관련 화면을 갱신하고 opaque 커서 기반 `GET /api/users/:id/notifications`로 알림함을 보충한다. 이벤트 본문 자체는 알림 저장소가 아니다.
- UIKit SceneDelegate의 실제 활성/비활성 신호로 연결을 시작·종료한다. UIKit에서 호스팅한 SwiftUI scenePhase 값에만 의존하지 않는다.
- 첫 커서가 없으면 최근100개 이력을 알림함에 조용히 복원하고 이후 신규 알림부터 배너를 발행한다. 기존 저장 커서는 임의 초기화하지 않는다.
- 재연결·앱 복귀 때 누락을 조회하고 이벤트 ID로 중복을 제거한다. 20초 heartbeat·60초 피드 안전망이 있으며, 연결 실패 중에도 최대 30초 백오프 재시도와 REST 조회로 복구한다. 고객센터·운영자 신청 알림은 이 피드 안전망을 사용한다.
- 앱이 비활성화되면 연결을 닫는다. 백그라운드 30초 깨우기나 앱 미실행 알림은 구현하지 않는다. **APNs는 Apple Developer Program 가입·인증 설정 후 후속 구현**이며 지금은 앱 외부 즉시 알림을 보장하지 않는다.
- **탭 딥링크** — 일반 채팅은 해당 방, 고객의 예약 접수·확정·가게 사정 취소는 달력 아이콘과 예약 내역, 사장님의 새 요청·고객 취소는 받은 예약 요청, 알림장 도착은 알림장 아이콘과 해당 예약의 읽기 전용 알림장으로 이동한다.
- **알림 1회 원칙** — 채팅에 남는 예약·알림장 안내는 메시지 ID를 유지하면서 명시적 이벤트 문맥으로 개별 분류한다. 일반 채팅만 방별로 묶고 예약 축과 중복 생성하지 않는다. 채팅 제목은 보호자에게 가게명, 점주에게 고객명이며 본문에 새 채팅 안내를 표시한다. 열려 있는 같은 채팅방의 일반 채팅 배너는 생략한다. 예약 안내는 카카오톡으로 바꾸지 않고 기존 회색 시스템 안내문을 유지한다.

## 3. 가게 상세

- 가게 이름·주소·타입(호텔🏨/유치원🏠) 카드. 이름·프로필 박스 모서리는 14pt로 줄인다.
- **지도에서 보기:** 외부 앱 대신 앱 내부 카카오 SDK 지도창에서 해당 가게 단일 핀·확대한 지도·이름/주소를 표시한다. 닫아도 홈 지도 탐색 상태는 바뀌지 않으며 유효 좌표가 없으면 안내한다.
- 공유는 가게 키만 담은 HTTPS 상세 링크를 보낸다. 공개 랜딩의 “앱에서 열기”로 설치된 앱의 해당 가게에 진입하며 로그인 전 링크도 로그인 후 처리한다. Personal Team에서는 Universal Link 대신 사용자 동작 기반 커스텀 URL scheme을 사용한다.
- **주소 정밀 보강** — 공공데이터의 마스킹 주소(`***`)를 **네이버 지역 검색 우선**(층·건물·호까지 상세)으로 교체, 전화·카카오맵 링크는 카카오로 보강, 둘 다 없으면 좌표→지번 폴백. 동명 타지역 오매칭은 핀 좌표 3km 검증으로 차단.
- **찜(하트) 토글** — 서버 저장, 마이페이지 찜 목록과 연동.
- **내 가게 뱃지** — 로그인한 사장님이 등록한 가게면 '내 가게' 표시.
- **우리 아이 리뷰** — 이 가게에 남겨진 보호자 리뷰(평균 별점 + 보호자 수 + 태그). '리뷰 쓰기'로 작성 시트 진입.
- **블로그 후기** — 네이버 블로그 검색 결과 표시(NCP NAVER API HUB 경유, 2026-07-17 활성화).
- **맡기기 전 체크리스트** — 위탁 전 확인사항 안내.
- **일반 업체와 파트너 분리** — 미검증 일반 업체는 기본 정보만 보여주고, 관리자 승인 파트너만 서버 capability에 따라 예약·채팅·알림장·리뷰를 활성화한다.
- **문의하기(💬)** — 채팅 capability가 있는 파트너에서만 이 가게와의 채팅방으로 이동한다.
- **예약하기** — 예약 capability가 있는 파트너에서만 예약 화면으로 이동한다.

## 4. 예약

### 예약 신청 (BookingView)
- 날짜는 네이티브 달력의 검은 선택원으로 표시하며 월/연도 탐색과 실제 선택을 분리한다. 오늘은 KST 자정부터 선택 가능하고, 월 탐색만으로 선택일을 바꾸지 않는다. 자정 이후의 과거 선택은 표시·바인딩·제출 직전에 정규화한다. 하단 신청 패널은 실제 높이만큼 스크롤 영역을 확보하여 가격 안내 마지막 부분을 가리지 않는다. 하단 안전영역과 그림자 여백을 확보해 버튼과 패널 구분선을 위로 올린다.
- **강아지 선택** — 등록해 둔 우리 아이 목록에서 선택(이름·나이·견종·몸무게·메모 요약 표시).
- **보호자 정보** — 연락처·주소 입력, '자동 불러오기'로 프로필 값 채움. 입력값은 다음 예약을 위해 영구 저장.
- **서비스 선택** — 가게 상세의 수집 가격표에서 시간·종일·숙박 키워드에 맞는 실제 안내 행을 표시한다. 매칭되는 가격이 없으면 임의 금액을 만들지 않고 업체 확인 안내를 표시한다. 앱 안에서 결제나 총액 계산은 하지 않는다.
- **날짜·시간** — 캘린더(그래픽 DatePicker)에서 오늘 이후 원하는 날짜를 자유롭게 선택. **시간권만** 시작 시간(시간 피커로 자유 선택) + 이용 시간(1~6시간)을 고르고, 종일권·하루 숙박권은 날짜만 선택한다. 예약 문자열은 연도 포함 형식(시간권 "2026-07-12 (일) 14:00", 종일권·숙박권 "2026-07-12 (일)")으로 저장된다.
- **요청사항** — 알레르기·사료·산책 등 자유 입력.
- 신청 버튼 위에 **"가게 사정으로 예약이 취소될 수 있어요. 취소되면 채팅으로 알려드려요."** 경고 문구 표시.
- 강아지 선택칩은 해당 반려견의 실제 원형 사진을 표시하며 사진이 없으면 기본 아바타를 사용한다. 선택된 카드의 외곽 테두리만 안쪽2pt 주황색으로 표시하고 원형 사진에는 테두리를 두지 않는다.
- 신청 시 `POST /api/reservations` → 예약(REQUEST 상태)과 **채팅방이 자동 생성**되고, 완료 화면에 제출 순간 선택한 강아지의 실제 원형 사진과 가게·강아지·일정·가격 참고 안내가 표시되며 바로 채팅방으로 이동할 수 있다.

### 기기 캘린더 선택 저장
- 예약 완료 화면에서 사용자가 **캘린더에 추가**를 누를 때만 권한을 요청하고 고객 기기에 예약 신청 일정을 추가한다. 사장님 기기에는 저장하지 않는다.
- 삭제: 본인이 취소하면 즉시, 사장님이 취소한 경우엔 고객이 예약 내역을 열 때 CANCELED 상태를 감지해 삭제(서버 푸시 없음).
- 캘린더 권한이 거부돼 있으면(iOS는 시스템 알림을 다시 안 띄움) **"캘린더 권한이 꺼져 있어요" 알림으로 설정 앱 이동을 안내** — 예약 자체는 정상 처리.

### 예약 내역 (ReservationListView)
- 지금까지의 예약을 카드로 표시 — 가게명·일정·서비스 타입·상태(예약 요청됨/예약 확정/예약 취소됨), 호텔🏨/유치원🏠 아이콘.
- REQUEST/CONFIRMED 상태면 **예약 취소** 가능(확인 알림 + 낙관적 업데이트, 실패 시 원상복구).

### 알림장 (DiaryTimelineView)
- 양쪽 확정예약 목록과 알림장 상단에 해당 반려견의 실제 원형 사진을 표시한다. 요청·확정 예약의 해당 ACTIVE 승인 점주에게만 예약별 사진 읽기를 허용하고 사진 교체·삭제는 본인만 가능하다.
- **예약당 타임라인** — 사장님이 맡은 아이의 하루("초코가 친구들과 잘 놀았어요")를 글로 남기고, 보호자가 그 예약 단위로 열람한다.
- 예약 한 건의 전체 기록을 최초 게시 시각순으로 유지하며, 한국 시간 게시일의 첫 글 위에만 `2026년 12월 1일` 같은 가운데 작은 날짜 라벨을 표시한다. 카드에는 시간만 표시한다. 첫 글/하루 전체 삭제 시 라벨도 자동 재계산하고 수정은 최초 게시일을 바꾸지 않는다. 해석할 수 없는 게시일은 ‘날짜 확인 필요’ 그룹으로 남긴다. 보호자·사장님 공통이며 예약 이용일로 알림장을 필터링하지 않는다.
- **사장님(작성):** 홈 사이드바 [사장님 메뉴] '예약 관리' → 확정 예약 → 알림장 탭에서 작성/수정/삭제(`DiaryComposer` 시트).
- **보호자(열람):** 홈 사이드바 '확정예약·알림장' → 내가 확정한 예약(맡긴 아이들) 목록(`MyDiaryListView`) → 같은 화면을 읽기 전용으로 사용(`diaryContext.canWrite` 플래그로 시점 분리 — 채팅 말풍선과 같은 패턴). 예전엔 예약 내역 확정 카드의 '알림장 보기' 버튼이었으나, 사장님 전용 버튼들과 섞여 혼동을 준다는 피드백으로 사이드바로 이전.
- 사장님이 **작성할 때만** 보호자 채팅방에 자동 메시지(sender 0) 발송 — 안 읽은 채팅 빨간 점에 자동 반영. 수정·삭제는 메시지 없음.
- 사장님은 알림장당 사진을 최대 3장까지 시스템 사진 선택기에서 추가·삭제한다. 앱은 원본 5MB를 제한하고 최대 1600px·1.5MB JPEG로 정규화해 비공개 R2에 저장한다. 보호자와 해당 가게 사장님만 인증된 사진 API로 열람하며, 카드를 누르면 전체 화면에서 좌우로 넘겨볼 수 있다.

### 예약 관리 (사장님, OwnerModeView)
- 사장님 메뉴의 단일 **예약 관리**에서 요청/확정 두 탭으로 조회한다. 카드에는 반려견·보호자·가게·일정·서비스를 표시한다.
- 확정 탭은 한국 이용일 기준 주간 날짜·월 달력·오늘 버튼으로 탐색한다. 해당일 건수/예약 유무를 표시하고 여러 날 예약은 시작~종료일 각 날짜에 같은 예약을 보여준다. 날짜 불명/역전된 기간은 ‘날짜 확인 필요’에서 접근한다. 선택일은 상세 왕복·실시간 갱신에 유지하고, 확정 직후·알림 직접 진입은 예약 시작일을 선택한다. 계정 전환/재시작은 오늘로 초기화한다.
- 카드를 누르면 **예약 상세**로 이동한다. 요청 상태에서는 정보 확인 후 확정/취소하고, 확정 성공 시 같은 화면에 정보/알림장 두 탭을 표시한다. 확정 카드의 알림장 작성은 바로 해당 탭으로 진입한다.
- 주의사항(알레르기·사회성·특이사항), 강아지 정보, 보호자 연락처·주소, 예약 일정·서비스·요청사항을 확인한다. 누락 정보는 미입력으로 구분한다.
- 시간권은 선택한 한국 시작 시각에 요청 hours를 더해 종료를 저장하고 상세에 분 단위로 표시한다. 과거 start=end인 시간권도 요청 hours로 종료를 계산하며 잘못된 기간·시각은 추정하지 않는다.
- 새 예약은 신청 순간의 계정·반려견 정보와 예약 화면 입력 연락처·주소를 별도 보관한다. 프로필 변경 후에도 유지하며, 스냅샷이 없는 과거 예약은 현재 정보 기준임을 명시한다. 사진은 기존 인증 경로를 사용한다.
- 조회·확정·취소는 해당 가게의 현재 승인된 점주만 가능하며 취소 예약과 승인 해제 시 상세 접근을 차단한다. 알림 수신으로 갱신해도 작성 중인 알림장 상태를 유지한다.

## 5. 채팅

### 손님 ↔ 사장님 양방향 채팅
- 채팅방은 **(손님 + 가게) 조합당 1개**. 사장님용 방을 따로 만들지 않고 같은 방에 각자의 `sender_id`로 참여한다 — 말풍선 방향은 "내가 보낸 메시지인가" 기준이라 양쪽 시점 모두 자연스럽다.
- 예약하면 방이 자동 생성되고, 가게 상세 '문의하기'로도 진입 가능(방이 없으면 첫 전송 때 생성).

### 채팅 목록 (ChatListView)
- **받은 문의** 섹션(사장님 전용) — 내가 등록한 가게로 온 손님들의 문의방 목록(손님 닉네임 + 가게명 + 마지막 메시지). 보호자 프로필은 강아지 아바타(dog_b/dog_c, 방마다 고정 순환)로 표시.
- **내 채팅** 섹션 — 내가 손님으로서 가게에 보낸 채팅방 목록. 가게 프로필은 타입별 아이콘(유치원 kindergarden / 호텔 hotel)으로 표시.

### 채팅방 (ChatRoomView)
- 실제 메시지 로드/전송. 전송은 낙관적 추가(실패 시 롤백), 방을 열어두는 동안 **3초 간격 폴링**으로 상대 메시지 자동 반영.
- 상단·상대 말풍선 프로필은 채팅 목록과 동일 — 손님 시점은 가게 타입 아이콘(유치원/호텔), 사장님 시점은 보호자 강아지 아바타(`AppRouter.chatRoomAvatar`, 진입점마다 설정).
- 방을 열람하면(최초 로드 + 보는 중 도착분) 마지막 메시지까지 **읽음 처리** — 홈 종 아이콘 빨간 점의 기준이 된다.
- 예약 시 "예약 요청이 완료되었습니다" 등 **자동 메시지**(sender 0 — 예약 취소 안내·리뷰 요청·알림장 알림 포함)가 방에 남는다 — 말풍선이 아니라 화자 없는 **중앙 정렬 시스템 안내문**(작은 글씨 + 크림색 칩)으로, 손님·사장님 양쪽 시점 동일하게 표시.
- **리뷰 요청 자동 메시지** — 확정된 예약의 이용일 다음날 오후 6시(KST), 서버 Cron이 그 채팅방에 "어제 ○○ 이용은 어떠셨나요? 리뷰를 남겨주세요" 메시지를 자동 발송(예약당 1회, 연·월·일 정확 대조).
- **예약 취소 자동 메시지** — 사장님이 예약을 취소하면 그 즉시 고객 채팅방에 "가게 사정으로 ○○ 예약(일시)이 취소되었어요" 메시지를 자동 발송(고객 본인 취소는 미발송).
- 상단 '응답중' 상태 표시는 손님 시점에서만 노출(사장님 시점에선 숨김).

## 8. 강아지(우리 아이) 프로필

- 등록/목록/삭제/상세 CRUD(서버 `pets` 테이블 실연동).
- 항목: 이름, 나이, 성별, 견종, 몸무게, 메모(사회성·알레르기·특이사항 병합).
- 갤러리에서 원본 최대 50MB 사진을 선택하고 최대 1600px·1.5MB JPEG로 최적화한다. 원형 크롭에서 원의 크기/위치와 사진 이동/확대를 조정한 뒤 체크로 적용하며 취소는 이전 사진을 유지한다. pinch/drag 중 한 제스처가 먼저 끝나도 마지막 확대·위치를 유지해 미리보기와 같은 영역을 적용한다. 목록·상세·등록 미리보기는 모두 원형으로 표시한다. 최종 정사각 JPEG를 비공개 Cloudflare R2에 계정·반려견별로 저장하고 원형으로 표시한다. 사진 조회·교체·삭제는 보호 API로만 허용하며 탈퇴·반려견 삭제 시 파일도 정리한다. 기존 Base64 사진도 읽으며 사진 미등록/읽기 실패 시 발자국 대신 dog_c 아바타를 표시한다. 직접 카메라 촬영은 아직 제공하지 않는다.
- 예약 화면의 강아지 선택 목록이 여기서 등록한 데이터를 쓴다.

## 9. 마이페이지

- **프로필 카드** — 외곽14pt 주황 카드의 이름 + 실데이터 통계(예약 수·강아지 수·채팅 수).
- **프로필 편집** — 이름·연락처·주소·선택 이메일 시트 편집. 이메일은 형식 검사 후 저장하고 빈 값으로 지울 수 있으며 카카오 계정 이메일 자체를 바꾸지는 않는다. 로그인 상태면 서버(`PUT /api/users/:id`)에도 저장 + 세션 닉네임 동기화. 기존 로그인 세션으로 앱을 다시 열 때도 `GET /api/auth/me`로 네 필드를 최신화하며, 계정/서버 전환·지연 조회·편집 중 덮어쓰기를 방지한다.
- **예약 내역 / 찜한 가게 / 채팅** — 각 화면으로 이동(개수 뱃지 표시).
- **내 가게** (사장님 전용) — `MyStoreSheet`에서 가게를 검색해 등록을 요청한다. 운영자 계정이 실제 소유 확인 후 승인해야 `stores.owner_id`가 연결되고 파트너 기능을 사용할 수 있다.
- **우리 아이 프로필** — 강아지 프로필 화면으로 이동.
- **로그아웃** — 확인 알림 후 로그아웃.
- **고객지원·설정** — 1:1 문의, 공지사항, 알림 설정, 개인정보처리방침, 도움말·지원, 오픈소스·아이콘 출처를 제공한다. 동작이 없던 쿠폰·공유·채팅 추가 버튼은 제거했다.

## 11. 백엔드 API 요약

배포: `https://matgyeomung-api.dog-kindergarden.workers.dev` (Hono + Cloudflare Workers + D1)

| 영역 | 라우트 | 용도 |
|---|---|---|
| 인증 | `POST /api/auth/kakao`, `POST /api/auth/logout` | 카카오 토큰 서버 검증, 30일 맡겨멍 세션 발급·폐기, 역할 불일치 409 |
| 사용자 | `PUT /api/users/:id` | 프로필(이름·연락처·주소) 저장 |
| 강아지 | `GET·POST /api/users/:id/pets`, `DELETE /api/pets/:petId` | 프로필 CRUD |

## 12. 핵심 데이터 규칙 (설계 불변식)

1. **공공 가게의 ID 승격** — 지도 가게는 DB id가 없으므로 `store_key`(`"이름|주소"`)로 `stores`에 upsert. 같은 가게는 항상 같은 `store_id`가 된다. 예약·찜·리뷰·채팅·내 가게 등록이 전부 이 규칙 위에 있다.
2. **채팅방·찜은 (사용자+가게)당 1개** — 예약마다 방을 만들지 않는다.
3. **역할은 계정 귀속** — 카카오 계정 하나 = 역할 하나(최초 가입 시 결정, 서버 409로 강제).
4. **캘린더는 고객의 명시적 선택으로만** — 예약 완료 화면에서 추가하고, 취소 시 생성했던 일정만 정리한다.

## 13. 미완성 · 데모 범위

- **일부 가게 주소 마스킹 잔존** — 네이버·카카오 어디에도 등록되지 않은 4곳은 DB에 마스킹 주소 유지(추측으로 채우지 않음) — 가게 상세 화면에서는 좌표→지번 폴백으로 최소한의 주소 표시.
- **회원 탈퇴** — 구현·운영 배포 완료. 마이페이지의 2단계 확인 후 본인 전용 API가 개인정보를 삭제·익명화하고 모든 세션을 폐기한다. 진행 중 예약이 있으면 완료·취소 전까지 차단한다.
- **로그인은 카카오뿐** — Apple 가이드라인 4.8은 제3자 로그인을 제공하면 Sign in with Apple도 동등한 옵션으로 제공할 것을 요구 — 실제 출시 전 추가 필요.
- **마이페이지 1:1 문의** — 사용자별 고객센터 대화와 운영자 전용 문의함·답장 API 및 화면 구현·운영 배포 완료.
- **원격 푸시 미구현** — 가입 전에는 §2의 포그라운드 WebSocket·누락 피드 복구만 제공한다. APNs 서버 발송·기기 토큰·인증·실기기 수신 검증은 Apple Developer Program 가입 후 진행한다.
- **API 인증** — 카카오 액세스 토큰을 서버에서 검증해 30일 세션을 발급하고, 보호 API는 Bearer 토큰의 사용자·역할·가게 소유권을 검사한다. 2026-10-16 운영 배포 후 무인증 타인 예약 조회가 `401`로 차단됨을 확인했다.
