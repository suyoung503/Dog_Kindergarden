# 미연결 UI·UX·권한 감사

**감사일:** 2026-10-10  
**범위:** 보호자·사장님 주요 SwiftUI 화면, Info.plist 권한 설명, 알림·백그라운드 처리  
**목표:** 출시 전에 오동작하는 핵심 흐름을 먼저 차단하고, 장식용 UI와 불필요한 권한을 제거한다.

**구현 현황:** 2026-10-12 가짜 예약 가격 제거와 수집 가격 참고값, 일반/파트너 기능 분리, 공유 버튼, 강아지 갤러리 사진, 운영자 1:1 문의, 주요 목록 공통 오류/재시도, 미사용 위치 권한 제거, 캘린더·알림 권한 요청 시점, 앱 내부 알림함과 백그라운드 사용자 복원, 가게 전화·외부 지도 연결을 완료했다. 실제 iPhone 검증은 남아 있다.

## 2. 예약 가격과 픽업

예약 화면은 업체가 입력한 가격이 아닌 시간·종일·숙박 고정 금액을 계산하고 있었다. 또한 픽업 선택 상태와 무관하게 픽업 비용이 총액에 더해지는 경로가 확인됐다.

운영 원칙은 다음과 같이 바꾼다.

- 파트너가 직접 등록하고 운영자가 노출 가능한 것으로 확인한 가격만 구체적인 금액으로 표시한다.
- 그 전에는 총액을 계산하지 않고 `가격은 업체마다 다릅니다. 예약 확정 전 업체와 확인해주세요.`로 안내한다.
- 픽업 가능 여부와 실제 비용을 별도 데이터로 관리하기 전에는 픽업 요금을 계산하지 않는다.
- 일반 업체는 앱 내부 예약 자체를 제공하지 않는다.

## 3. 권한 감사

### 위치

현재 `CLLocationManager` 기반 현재 위치 기능이 없는데 위치 사용 설명 키가 포함되어 있다. 기능을 사용하지 않는 동안 아래 키를 제거한다.

- `NSLocationAlwaysAndWhenInUseUsageDescription`
- `NSLocationWhenInUseUsageDescription`

향후 현재 위치 버튼을 실제로 구현할 때 `When In Use`만 복원하고, 사용자가 버튼을 누른 시점에 사전 설명 후 요청한다. Always Location은 현재 요구사항에 필요하지 않다.

### 캘린더

예약 요청이 생성된 즉시 캘린더 일정을 추가하던 흐름을 다음과 같이 변경했다.

- 예약 완료 화면에서 사용자가 누르는 `캘린더에 추가` 버튼으로 분리했다.
- 예약 신청 일정임을 제목에 표시하고, 버튼을 누를 때만 권한을 요청한다.
- 같은 예약을 중복 추가하지 않으며 취소된 예약은 사용자가 추가한 캘린더 일정도 정리한다.
- 거부 시 예약 실패로 취급하지 않고 iOS 설정으로 이동하는 선택지를 제공한다.

### 알림과 백그라운드

- 로그인 직후 권한 요청을 제거하고, 마이페이지에서 예약·채팅 알림 가치를 설명한 뒤 사용자가 `알림 받기`를 누를 때만 요청한다.
- 마이페이지에 `설정 전/켜짐/꺼짐` 상태를 표시하고, 이미 결정된 권한은 iOS 설정으로 이동해 바꾸도록 안내한다.
- 거부해도 서버 알림 피드를 계속 조회해 계정별 앱 내부 알림함에 최대 100건을 보관한다.
- 홈의 종 아이콘은 전용 알림함으로 이동하고 읽지 않은 전체 이벤트를 빨간 점으로 표시한다.
- Background App Refresh 콜드 시작에서는 Keychain 세션과 저장된 사용자 번호가 모두 있을 때만 계정을 복원해 폴링한다. 실제 실행 여부는 기기에서 검증한다.

## 4. 미연결 또는 오해 가능한 UI

- 가게 상세 공유 아이콘: 동작 없음
- 채팅 입력창 `+` 버튼: 빈 action
- 채팅 스마일 아이콘: 버튼처럼 보이나 동작 없음
- 강아지 등록 카메라: `PhotosPicker`로 갤러리 사진 1장 선택·압축·저장 구현
- 전화번호·주소: 완료 — 일반·파트너 업체 모두 공통 `연락·위치` 영역에서 전화 앱과 외부 지도로 연결하고, 마스킹·불완전 전화번호는 연결하지 않음
- Kakao 장소 URL: 완료 — 장소 URL을 우선 사용하고, 없으면 가게명·주소로 Kakao 지도 검색 URL을 생성
- `.cityMap`, `.kakaoMap`: 실제 진입 경로가 없는 라우트 후보

사용자가 누를 수 있다고 인식하는 요소는 동작을 구현하기 전까지 숨긴다. 단순 장식은 버튼 스타일을 사용하지 않는다.

## 5. 로딩·빈 상태·오류 상태

다음 화면은 오류를 빈 배열 또는 빈 화면으로 바꾸는 경로가 있어, 실제로 데이터가 없는지 서버 호출에 실패했는지 사용자가 알 수 없다.

- 지도 가게 목록
- 찜한 가게
- 보호자 예약 목록
- 사장님 예약 목록
- 알림장 목록·타임라인
- 내 가게 선택 화면
- 강아지 목록과 예약 화면의 강아지 로드
- 채팅 목록
- 가게 상세·리뷰·블로그 후기

`AsyncLoadPhase`로 `idle/loading/loaded(empty 포함)/failed` 상태를 분리하고 오류 화면에 재시도 버튼을 제공한다. 홈 지도·찜·예약·채팅·알림장·사장님 목록·내 가게 관리·가게 상세 리뷰와 블로그는 이 기준을 적용했고, 이전 데이터가 있으면 갱신 실패 때 비우지 않는다. 강아지 목록과 예약 화면의 강아지 로드는 추가 개선 범위다.

## 6. 문구·데이터 범위

- 내 가게 선택 화면의 `전국` 표현은 현재 서울 큐레이션 범위와 맞지 않으므로 실제 제공 지역으로 수정한다.
- 모든 가게에 공통으로 광견병 접종증명서와 사료 지참이 필요한 것처럼 보이는 정책 문구는 제거하거나 파트너가 직접 입력한 정책만 표시한다.
- 일반 업체와 파트너 업체의 예약·문의 가능 여부를 상세 화면에서 명확히 구분한다.

## 7. 권장 구현 순서

1. 고정 예약 가격과 일반 업체 예약 제거
2. 일반 업체/파트너 capability에 따른 화면·서버 차단
3. 사용하지 않는 권한과 죽은 버튼 제거
4. 지도·예약·채팅·알림장의 오류/재시도 상태 보강
5. 1:1 문의를 실제 응답 가능한 채널로 교체
6. 캘린더·알림 권한을 명시적 사용자 행동 시점으로 이동 — 완료
7. 실제 iPhone에서 거부·설정 변경·백그라운드 복귀 검증

## 8. 수동 검증이 필요한 항목

- 실제 iPhone의 위치·알림·캘린더 권한 거부와 설정 변경
- 실제 iPhone의 전화 앱·Kakao 지도 전환 및 앱 미설치/URL 열기 실패 안내
- 백그라운드·강제 종료 상태의 알림 피드 갱신
- 운영 D1의 개발자 카카오 계정 `is_admin=1` 지정과 두 계정 간 문의·답장 실기기 확인
- VoiceOver, Dynamic Type, 작은 화면에서의 버튼·오류 문구 접근성

실제 기기 결과가 없으면 권한 UI의 로컬 구현과 별개로 실제 기기 검증과 백그라운드 항목은 완료로 표시하지 않는다.
