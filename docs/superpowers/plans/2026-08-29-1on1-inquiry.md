# 1:1 문의 기능 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 마이페이지의 죽어있는 "1:1 문의" 버튼을 활성화해, 사용자가 개발자 본인 계정과 직접 채팅할 수 있게 한다.

**Architecture:** "고객센터"를 고정 `store_key`("맡겨멍 고객센터|고객센터")를 가진 가상 가게 1개로 취급해, 이미 존재하는 `store_key` 기반 채팅방 get-or-create·"받은 문의" 인프라를 그대로 재사용한다. 백엔드 코드 변경은 없다 — iOS에서 버튼 하나에 액션을 연결하고, 배포 후 1회성 curl 호출로 개발자 계정을 이 가상 가게의 `owner_id`로 지정한다.

**Tech Stack:** Swift 5.9 / SwiftUI (iOS), 기존 `ChatService`/`AppRouter`/`MapPin` 재사용. 백엔드는 기존 Cloudflare Workers + D1 API를 그대로 사용(코드 변경 없음).

## Global Constraints

- 고정 `store_key`는 정확히 `"맡겨멍 고객센터|고객센터"` 문자열이어야 한다 — 다른 값을 쓰면 프로비저닝 curl과 iOS 코드가 서로 다른 가게를 가리키게 된다.
- 백엔드(`backend-cloudflare/src/index.ts`)는 이 계획에서 **한 줄도 수정하지 않는다**.
- `StoreDetailView.openChat()`(`Dog_kindergarden/Dog_kindergarden/Views/StoreDetail/StoreDetailView.swift:518-530`)과 동일한 패턴(기존 방 있으면 재사용, 없으면 작성 모드)을 따른다.
- 커밋은 **실행자가 직접 `git add`/`git commit`을 실행하지 않는다** — 각 커밋 단계에서 정확한 명령어를 사용자에게 보여주고, 사용자가 자신의 터미널에서 직접 실행하도록 한다(이 프로젝트에서 확립된 규칙).
- iOS 빌드는 워크스페이스로: `xcodebuild -workspace Dog_kindergarden.xcworkspace -scheme Dog_kindergarden -destination 'platform=iOS Simulator,id=797D6EB2-6339-4855-B755-09EB8815A147' -derivedDataPath build build` (Dog_kindergarden/ 디렉터리에서 실행, `.xcodeproj`가 아닌 워크스페이스로 열 것 — CLAUDE.md). 이 destination(iPhone 17, OS 26.5)이 없으면 `xcrun simctl list devices available | rg "iPhone"`로 사용 가능한 iPhone 시뮬레이터의 UDID를 확인해 대체한다.
- 시뮬레이터 터치 자동화(osascript/System Events)는 이 환경에서 신뢰할 수 없는 것으로 이전 세션에서 확인됨 — 콜드 런치 시점에 보이는 화면은 스크린샷만으로 검증 가능하지만, 탭 이동이 필요한 화면(마이페이지 등)은 사람이 시뮬레이터에서 직접 탭한 뒤 스크린샷으로 확인해야 한다. 자동 검증이 불가능한 단계는 그렇다고 명시하고 사람에게 확인을 요청한다.

- [ ] **Step 2: `openSupportChat()` 메서드 추가**

`supportSection` 프로퍼티 바로 아래(또는 같은 `private extension`/구조체 내 아무 위치)에 추가:

```swift
// 1:1 문의 — "고객센터"를 고정 store_key를 가진 가상 가게로 취급해 기존 채팅 인프라 재사용.
// 기존 방 있으면 그 방으로, 없으면 작성 모드로 진입 (StoreDetailView.openChat()과 동일 패턴)
private func openSupportChat() {
    let key = "맡겨멍 고객센터|고객센터"
    Task {
        guard let uid = authSession.userId else { return }
        let rid = await ChatService.lookup(userId: uid, storeKey: key)
        router.selectedPin = MapPin(
            name: "맡겨멍 고객센터", type: "고객센터", rating: 0, distance: "",
            latitude: 0, longitude: 0, province: "",
            storeKeyOverride: key
        )
        router.selectedChat = "맡겨멍 고객센터"
        router.selectedRoomId = rid
        router.chatRoomAsOwner = false
        router.chatRoomAvatar = "🎧"
        router.go(.chatRoom)
    }
}
```

Task 1의 코드가 배포(App Store/TestFlight 또는 개발자 본인 기기 실행)된 뒤 **1회만** 수행하는 운영 작업이다. 코드 변경이 없으므로 별도 파일/Interfaces 섹션은 없다.

**Files:** 없음 (운영 작업, 백엔드 API 호출만)

- [ ] **Step 1: 개발자 본인의 실제 카카오 계정으로 사장님(owner) 역할 회원가입**

- [ ] **Step 2: 방금 가입한 계정의 `user_id` 확인**

`backend-cloudflare/` 디렉터리에서:

```bash
npx wrangler d1 execute dog_kindergarden_db --remote \
  --command "SELECT user_id, nickname, is_owner FROM users ORDER BY user_id DESC LIMIT 5"
```

방금 가입한 닉네임이 있는 행의 `user_id` 값을 확인한다(이하 `<DEV_USER_ID>`로 표기).

- [ ] **Step 3: 고정 "고객센터" 가게를 이 계정 소유로 지정**

```bash
curl -X POST https://matgyeomung-api.dog-kindergarden.workers.dev/api/stores/claim \
  -H "Content-Type: application/json" \
  -d '{"user_id": <DEV_USER_ID>, "store_key": "맡겨멍 고객센터|고객센터", "store_name": "맡겨멍 고객센터"}'
```

Expected: HTTP 201, 응답 바디에 `{"store_id": <숫자>, "owner_id": <DEV_USER_ID>}`. `<DEV_USER_ID>`는 Step 2에서 확인한 실제 정수 값으로 치환한다. 이 요청보다 먼저 사용자가 문의를 보내 가게 행이 이미 생성돼 있어도, 나중에 생성돼도 결과는 동일하다(`resolveStoreId`가 upsert하기 때문).

- [ ] **Step 4: claim 결과 검증**

```bash
curl -s https://matgyeomung-api.dog-kindergarden.workers.dev/api/owners/<DEV_USER_ID>/stores
```

Expected: 응답 배열에 `"name": "맡겨멍 고객센터"` 항목이 포함됨.

- [ ] **Step 5: 종단 간 수동 확인 (두 계정 왕복)**

이 단계는 실제 기기/시뮬레이터에서 사람이 직접 확인해야 한다(자동화 불가 — 로그인 전환이 필요):

1. 다른 계정(예: 기존 `dev-simulator` 견주 계정, 또는 다른 실계정)으로 로그인 → 마이페이지 → "1:1 문의" → 메시지 전송(예: "문의 테스트입니다").
2. 로그아웃 후 Step 1의 사장님 계정으로 재로그인 → 채팅 목록 → "받은 문의"에 방금 보낸 문의가 보이는지 확인.
3. 그 방에서 답장 전송.
4. 다시 처음 계정으로 로그인 → 같은 채팅방에 답장이 보이는지 확인.

각 단계가 자동 검증이 아닌 수동 확인임을 결과 보고 시 명시한다.
