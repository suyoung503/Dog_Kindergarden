### 3.1 실기기 수정안 17 — 실시간 갱신과 원격 알림

2026-10-24 사용자 확정 방향이며 2026-10-26 작업 브랜치 구현·로컬 검증 기준이다. 서버는 운영 배포했으며 APNs 후속 작업·최신 iOS 설치 후 실기기 검증과 구분한다.

- [x] **가입 전 구현:** 앱 사용 중에는 WebSocket으로 예약·채팅·알림장 변경 이벤트를 받아 앱 내부 알림과 관련 화면을 실시간으로 갱신한다.
- [x] 연결이 끊겼다가 재연결되거나 앱에 복귀하면 서버에서 누락된 변경을 조회해 반영하고, 같은 이벤트를 중복 알림으로 표시하지 않는다.
- [ ] **가입·인증 설정 후 진행:** Apple Developer Program 가입 활성화, Push Notifications 권한 및 APNs 인증 설정을 마친 뒤 앱·서버를 연동한다.
- [ ] 앱을 보고 있지 않을 때는 서버가 APNs로 시스템 알림을 보내도록 구현하고 실제 iPhone에서 수신과 알림별 화면 이동을 검증한다.

작업 브랜치는 포그라운드 WebSocket + 영속 피드 커서 복구로 전환했다. 20초 heartbeat·60초 피드 안전망·최대 30초 연결 재시도 백오프는 **앱이 활성화된 동안**만 동작한다. WebSocket만 실패해도 REST 복구 후 화면에 갱신 신호를 보낸다. 고객센터·운영자 신청 알림은 피드 안전망에 포함한다. 기존 백그라운드 새로고침 호출은 호환용 no-op으로 남겨 30초마다 앱을 깨운다고 설명하지 않는다. WebSocket만으로 백그라운드·앱 미실행 알림을 제공하지 않으며, APNs 서버 발송·기기 토큰 등록·권한·인증과 실제 수신 검증은 가입 후 별도 구현한다. APNs 연동 후에도 표시 시점은 사용자 설정·네트워크·iOS 상태의 영향을 받는다.
