## 0. 기본 원칙

- 현재 기능 수는 v1.0 출시 후보로 충분하다. 당분간 새 기능을 늘리지 않고 **전체 점검 → 보안·심사 블로커 해결 → 실사용 핵심 보완 → TestFlight → 실제 가게 파일럿 → App Store 제출** 순서로 진행한다.
- `Critical`과 `Major` 문제가 0건이 되기 전에는 후순위 기능을 추가하지 않는다.
- 지도에 노출되는 모든 업체와 실제 맡겨멍 서비스를 제공하는 업체를 같은 것으로 취급하지 않는다.
  - **일반 업체:** 공공데이터 기반 탐색 정보만 제공한다.
  - **맡겨멍 파트너:** 소유자 확인과 입점 동의가 끝난 업체로, 예약·채팅·알림장·리뷰를 제공한다.
- 사용 권한이 불명확한 크롤링 데이터는 즉시 무작정 삭제하기보다 먼저 출처를 분류하고, 운영 앱에서는 단계적으로 숨기거나 제거한다.
- 아래 로드맵이 기존 문서의 과거 우선순위보다 우선한다.

## 4. P0 — 사장님 가게 등록을 관리자 승인 방식으로 변경

`POST /api/stores/claim`으로 아무 사장님 계정이 미등록 가게를 직접 가져가는 구조를 중단한다.

- [x] 앱의 즉시 셀프 등록 기능을 제거하고 신청 상태로만 제한한다. — 사장님 화면에 승인 대기 상태 표시
- [x] v1.0은 `사장님 신청 → 운영자 확인 → DB에서 owner_id 연결` 방식으로 운영한다. — 운영자 전용 요청함·승인·거절 API와 화면 구현
- [ ] 초기 파일럿 가게 1~3곳만 직접 확인해 연결한다.
- [x] 승인 전에는 해당 업체의 예약·고객 정보·채팅·알림장에 접근할 수 없게 한다. — 승인 전 `stores.owner_id` 미연결 및 객체 소유 관계 검사
- [x] 새 가게 등록 요청을 운영자 알림 피드에 연결한다. — 운영자에게만 로컬 알림을 만들고 탭하면 승인 요청함으로 이동
- [ ] 승인·해제·소유권 변경 이력을 남길지 결정한다.
- [ ] 사업자등록증 자동 인증이나 복잡한 입점 시스템은 v2로 미룬다.

**운영 방식:** `users.is_admin=1`은 앱 입력으로 얻을 수 없고 운영 D1에서 개발자 실계정에만 수동 부여한다. 운영자 화면에는 신청자의 닉네임·연락처·이메일·주소와 가게 정보가 표시된다. 실제 사업자 여부는 이 정보를 사업자등록증 등 별도 자료와 운영자가 직접 대조한 뒤 승인한다. 등록 요청과 승인·거절 상태, 처리 운영자, 처리 시각은 `store_owner_applications`에 남긴다. 2026-10-16 개발자 실계정에 운영자 권한을 부여하고 운영 D1/Worker에 반영했다.

## 8. P0 — 데이터 출처와 업체 유형 분리

### 8.1 먼저 할 일: 데이터 출처 전수 분류

현재 데이터를 바로 삭제하지 않고 각 필드·이미지의 출처부터 매핑한다.

- [x] 업체 기본정보, 주소, 전화, 위치, 영업 상태, 영업시간, 가격, 대표 이미지, 추가 이미지, 편의정보 각각의 출처 조사 — 코드·기본 로컬 D1 기준 [`DATA_PROVENANCE_AUDIT.md`](DATA_PROVENANCE_AUDIT.md)에 기록, 운영 D1 대조는 배포 전 필요
- [x] 출처 값 설계: `PUBLIC_DATA`, `NAVER_PLACE_CRAWL`, `NAVER_SEARCH_API`, `KAKAO_API`, `HOMEPAGE`, `OWNER`, `USER_REVIEW`, `ADMIN`
- [x] 가게 행 하나에 출처 하나만 두지 않고 필드별 `store_field_facts`와 이미지 자산 출처 구조 설계
- [x] `source_url`, 수집일, 최종 확인일, 사용 권한 상태가 필요하다고 결정 — `collected_at`, `verified_at`, `rights_status`, `verification_level` 포함
- [x] 현재 약 1,138장 추가 이미지, 199개 업체 가격, 284개 업체 영업시간의 출처와 앱 노출 경로 우선 점검
- [x] 운영 앱에서 `naver_crawl` 출처 데이터를 숨길 수 있는 기능 플래그 또는 조회 조건 추가 — `EXPOSE_UNVERIFIED_STORE_DETAILS=false`가 일반·파트너 모두의 미검증 영업시간·가격·이미지·편의정보를 차단
- [ ] 출처 분류와 백업이 끝난 뒤에만 불필요한 크롤링 데이터를 단계적으로 삭제

### 8.2 네이버 데이터 사용 조건 점검

## 18. 수익화 메모

수익 모델보다 파트너 가게와 실제 보호자 사용을 먼저 검증한다.

- 일반 업체 데이터는 사용자에게 탐색 가치를 제공한다.
- 파트너 업체는 예약·채팅·알림장 등 실제 서비스 가치를 제공한다.
- 초기에는 `일반 업체 285곳 + 파트너 1곳`이어도 된다.
- 파트너를 1곳 → 3곳 → 5곳으로 늘린 뒤 사장님용 구독, 상단 노출, 광고 슬롯 등을 검토한다.
- 실사용자와 파트너가 없는 상태에서는 결제·구독 시스템부터 만들지 않는다.
