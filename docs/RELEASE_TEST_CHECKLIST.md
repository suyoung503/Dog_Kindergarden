# 맡겨멍 실제 기기·외부 서비스 수동 테스트 체크리스트

자동 smoke로 대체할 수 없는 항목만 모은 체크리스트다. 각 항목은 실제로 실행한 뒤에만 체크한다.

## 0. 실행 정보

- [ ] 테스트 대상 Git 커밋을 기록했다.
- [ ] 앱 버전과 빌드 번호를 기록했다.
- [ ] iPhone 모델, iOS 버전, Xcode 버전을 기록했다.
- [ ] 테스트 환경(개발/스테이징/운영 Worker와 D1)을 기록했다.
- [ ] 보호자·사장님·운영자 계정은 서로 다른 실제 계정으로 준비했다.
- [ ] 테스트 가게와 테스트 데이터가 실제 운영 데이터와 구분된다.

## 1. 설치와 앱 수명주기

- [ ] Release configuration을 실제 iPhone에 설치하고 첫 화면까지 실행된다.
- [ ] 앱 종료 후 재실행해도 인증 상태와 화면이 정상 복구된다.
- [ ] 백그라운드 전환 후 복귀해도 화면과 데이터가 정상이다.
- [ ] 앱을 강제 종료한 뒤 알림 또는 딥링크로 정상 진입한다.
- [ ] 이전 버전 위에 업데이트해도 Keychain과 사용자 데이터가 의도대로 유지된다.
- [ ] 삭제 후 재설치 시 남아야 할 정보와 삭제될 정보가 정책과 일치한다.

## 2. 실제 계정 인증

- [ ] 신규 카카오 계정으로 가입한다.
- [ ] 기존 카카오 계정으로 재로그인한다.
- [ ] 카카오 앱이 있는 경우와 없는 경우 모두 확인한다.
- [ ] 로그아웃 후 다른 계정으로 로그인했을 때 이전 계정 데이터가 보이지 않는다.
- [ ] 만료·폐기된 세션에서 로그인 화면으로 안전하게 돌아간다.
- [ ] Apple 로그인 신규 가입·재로그인·로그아웃을 확인한다.
- [ ] Apple 이메일 가리기와 이름 최초 1회 제공을 확인한다.
- [ ] 회원 탈퇴 후 기존 토큰으로 API를 사용할 수 없다.
- [ ] 두 기기에서 예약 신청과 고객/사장님 탈퇴가 겹칠 때, 예약 성공이면 탈퇴가 거절되거나 탈퇴 성공이면 새 예약이 거절된다. 기존 예약·프로필·사진이 절반만 지워지지 않는다.
- [ ] 다른 기기 탈퇴와 프로필 저장·강아지 등록이 겹쳐도 탈퇴 후 서버 개인정보가 다시 저장되지 않으며 실패 안내가 표시된다.
- [ ] 로그인 전과 마이페이지에서 이용약관·개인정보처리방침을 열 수 있고, 탈퇴 전 보유기간 링크와 로그인 없이 열리는 고객지원의 탈퇴 절차가 정상이다. `/terms` 준비안 표시가 남은 빌드를 정식 약관 적용 완료로 제출하지 않는다.
- [ ] 탈퇴 전 삭제/남는 기록·사진 삭제 지연·가게 연결 종료·카카오 계정 자체는 유지됨을 읽고 최종 확인할 수 있다. 기본 탈퇴를 이메일/전화로 강제하지 않으며 모든 기기의 후속 보호 API가 차단된다.
- [ ] 별도 로컬/스테이징에서 사진 저장소 삭제 장애를 만든 뒤 탈퇴해도 사진 API는 차단되고, 장애 복구 후 정리에서 파일·대기 기록이 제거된다. 운영 저장소에 의도적 장애를 만들지 않는다.
- [ ] 스테이징에서 탈퇴 응답을 지연시킨 동안 세션 만료→다른 계정 재로그인 또는 같은ID 새 세션/API 전환 후 응답을 전달해도 현재 프로필·인증·알림·캘린더 연결·화면·오류 안내가 초기화/덮어쓰기되지 않는다. 서버 탈퇴 완료와 화면의 오래된 결과 무시를 구분한다.
- [ ] 같은 API에서 탈퇴200 전에 세션 만료가 먼저 반영되거나 토큰만 먼저 지워진 경우에도 과거 프로필/알림/최근 가게/캘린더 연결이 정리된다. UID/token nil만으로 정리를 허용하지 않으며 B 로그인→로그아웃 뒤 B 캐시는 보존되는지 함께 확인한다.
- [ ] 늦은 탈퇴 성공이 A의 저장키를 지워도 새 계정 B의 알림함·딥링크·채팅·현재 화면·저장값은 유지된다. 만료 후 정리로 카카오 로그인이나 화면 이동을 다시 실행하지 않으며 실제 기기 캘린더 일정 자체는 남는다.
- [ ] API 서버 전환 또는 응답 전 앱 프로세스 종료의 과거 캐시 보유/복구 기준을 별도 확정한다. 실행 중 동일 API의 정리가 통과했다고 이 경계까지 완료로 표시하지 않는다.

### 2.1 약관·동의 기능 구현 후 추가 확인 — 현재 미구현

현재는 준비안 열람만 가능하다. 아래는 [기술 설계3.32](DEPLOYMENT_REMAINING.md)에 따른 후속이며, 실제 동의·버전 기록 기능과 최종 정책이 준비된 뒤에만 실행/체크한다.

- [ ] 최종 문서의 버전·시행일·항목과 앱에 표시된 내용이 같고, 준비안/미래 시행 문서를 현재 필수 동의로 받지 않는다.
- [ ] 미선택·거부·로그인 중단과 선택 항목 거부가 구분되고, 동의 화면에서 문서를 읽고 돌아와도 선택을 임의로 완료하지 않는다.
- [ ] 다른 기기의 같은 계정은 서버 기록을 확인하며, 다른 계정·API로 전환하면 이전 수락 표시가 넘어오지 않는다.
- [ ] 필요한 재동의를 거부하더라도 문서 열람·로그아웃·탈퇴·권리 행사 문의가 가능하다.
- [ ] 예약 시 실제 가게/수신자와 제공 범위를 확인하며, 제출 전에 가게/정식 버전이 바뀌면 내용을 다시 확인한다. 생성 후 소유자 변경/재승인에도 과거 예약·사진·채팅의 접근이 확정된 정책과 일치한다.
- [ ] 느린 연결·중복 탭·저장 실패·응답 유실 뒤 재시도에서 허위 완료/부분 동의/중복 기록이 없고, 구형 앱에서도 서버 조건이 유지된다.
- [ ] 선택 동의 철회·탈퇴 후 재가입·보유기간 종료의 기록 처리가 최종 정책과 일치한다. 실제 계정 검증은 승인된 스테이징/테스트 계정에서 수행한다.

#### 사용자 선택 운영안 구현 후 추가 확인 — 미시행·미실행

선택 항목의 원본은 [배포 문서3.32](DEPLOYMENT_REMAINING.md)의21개 질문표다. 아래는 새 기능이 구현된 뒤 수행할 조건이며 이번 문서 저장으로 통과 처리하지 않는다.

- [ ] 이메일 미제공 상태도 가입 가능하고 추가 카카오 개인정보를 자동 요청하지 않는다. 예약 실명과 프로필 닉네임을 구분하고 실명 인증 결과로 표시하지 않는다.
- [ ] 연락처는 가입/탐색에서는 선택이고 예약 신청 시 확인한다. 문자 인증은 무과금 운영이 확인되기 전까지 연동하지 않고 번호 형식 검사를 실제 소유 확인으로 표시하지 않는다.
- [ ] 가입·예약의 만19세 이상 자기확인과 서버 조건을 확인하되, 성인 인증 완료로 표시하거나 이를 위해 생년월일/신분증을 추가 수집하지 않는다.
- [ ] 종일권·시간권·숙박권 각각에 픽업 추가 체크가 가능하다. 미지원 가게에서는 선택할 수 없고 무료/유료 모두 기본 미선택이며 입실 편도만 제공한다.
- [ ] 채팅 협의와 예약별 최종 픽업 조건 등록·고객 확인·가게 예약 확정의 순서를 확인한다. 조건 변경 후 오래된 확인을 재사용하지 않고 개인정보 동의와도 혼동하지 않는다.
- [ ] 픽업 미선택 예약은 주소를 요구/제공하지 않는다. 재사용 저장을 명시적으로 선택하지 않으면 계정 주소에 자동 반영하지 않고, 선택 저장 주소는 해당 계정이 수정·삭제할 수 있다.
- [ ] 승인된 해당 가게만 신청 단계의 연락처와 해당 픽업 예약 주소를 조회한다. 계정에 저장한 다른 주소나 다른 가게/고객의 주소는 노출하지 않는다.
- [ ] 이용 종료 후 상세 주소의 가게 재조회 차단과 불필요해진 예약별 주소 파기를 별도로 확인한다. 삭제한 예약 주소를 현재 프로필 주소로 폴백해 재노출하지 않는다. ‘내 주소’·스냅샷·캐시·채팅 원문의 처리 범위와 법령상 보존 적용 여부를 확정한 뒤 검증한다.
- [ ] 완료 예약의 알림장/사진 보관과 현재5년 정리의 정합성을 확인한다. 사장님 탈퇴 후 보호자 열람 유지, 새 운영자의 과거 완료 기록 비공개, 진행 예약 인계의 별도 확인을 검증한다.
- [ ] 기본 취소·상대방 알림을 유지하고, 별도 금전 정책 등록·위약금 계산·결제/자동 환불 없이 역할과 정산 문의를 간단히 안내한다. 공식 문의 이메일은 선택한 기존 주소와 일치한다.

## 3. 권한과 외부 앱

- [ ] 지도 탐색과 핀 선택이 정상이며 앱이 위치 권한을 요청하지 않는다.
- [ ] 사진 권한 허용·제한·거부 상태에서 대체 흐름이 정상이다.
- [ ] 캘린더 권한 허용 후 일정 생성과 예약 취소 시 일정 삭제가 정상이다.
- [ ] 캘린더 권한 거부 시 예약 자체는 깨지지 않는다.
- [ ] 캘린더에 추가하지 않은 예약을 취소할 때 캘린더 권한 팝업이 나타나지 않는다.
- [ ] 추가한 일정의 권한을 설정에서 끄고 예약을 취소한 뒤, 권한 재허용·예약 내역 재조회로 해당 일정만 삭제되는지 확인한다(취소 내역 조회 가능한7일 내).
- [ ] 기기 시간대를 변경해도 시간권은 한국 예약 시각에 대응하는 시점이고, 종일 일정은 같은 날짜로 표시된다. 실제 일정의 시작·종료와 표시를 캘린더 앱에서 확인한다.
- [ ] 자정에 DST가 시작되는 기기 시간대의 종일 일정도 정상 생성된다. 실제 기기는 해당 지역의 향후 전환일을 테스트용 예약으로 준비한다. `America/Santiago`의2026-09-06은 자동 회귀 fixture이며 과거 날짜를 앱에서 새로 예약하라는 뜻이 아니다. 격리 날짜 검사가 실제 EventKit 표시를 대신하지 않는다.
- [ ] 알림 권한 허용·거부 후 앱 내부 알림 피드는 정상이다.
- [ ] 카카오맵 렌더링, 가게 위치 내부 지도창 열기·닫기, 전화 연결이 실제 기기에서 정상이다.

## 4. 보호자 전체 흐름

- [ ] 프로필을 조회하고 수정한다.
- [ ] 강아지를 등록·조회·삭제한다.
- [ ] 지도에서 업체를 탐색하고 필터를 사용한다.
- [ ] 일반 업체와 맡겨멍 파트너 상세의 기능 차이가 정확히 표시된다.
- [ ] 찜을 추가·해제한다.
- [ ] 파트너 업체에 문의하고 채팅을 송수신한다.
- [ ] 파트너 업체에 예약을 신청한다.
- [ ] 예약 내역을 조회하고 취소한다.
- [ ] 알림장을 확인하고 사진을 전체 화면으로 확인한다.
- [ ] 이용 완료 후 리뷰를 작성한다.
- [ ] 이용 이력이 없는 가게에는 리뷰를 작성할 수 없다.
- [ ] 같은 이용 건에 두 기기에서 리뷰를 제출하면 한 건만 저장되고 다른 화면은 재확인 안내를 표시한다. 작성 자격을 읽은 뒤 예약이 취소되거나 가게 연결이 종료돼도 새 인증 리뷰를 저장하지 않는다.
- [ ] 테스트 리뷰3개 중 시설 찬성1개는 홈 시설 필터에서 제외되고2개부터 포함된다. 짝수는 정확히 절반도 포함하며, 새로 집계 데이터를 읽은 상태에서 확인한다.

## 5. 사장님·운영자 전체 흐름

- [ ] 사장님 계정으로 가입하고 가게 등록을 요청한다.
- [ ] 승인 전에는 고객·예약·채팅·알림장에 접근할 수 없다.
- [ ] 운영자 계정에 등록 요청과 신청자 정보가 표시된다.
- [ ] 운영자가 실제 소유 증빙을 확인한 후 승인 또는 거절한다.
- [ ] 승인된 사장님에게 자기 가게만 표시된다.
- [ ] 자기 가게의 예약 요청만 수신하고 승인·취소할 수 있다.
- [ ] 고객과 채팅하고 알림장을 작성·수정·삭제한다.
- [ ] 다른 사장님 가게의 고객·예약·채팅·알림장에 접근할 수 없다.

## 6. APNs와 딥링크

- [ ] 새 예약 요청 Push가 사장님 기기에 한 번만 도착한다.
- [ ] 예약 승인·취소 Push가 보호자 기기에 한 번만 도착한다.
- [ ] 새 채팅과 새 알림장 Push가 대상 사용자에게만 도착한다.
- [ ] 포그라운드·백그라운드·강제 종료 상태에서 각각 수신한다.
- [ ] 알림을 누르면 정확한 예약·채팅·알림장 화면으로 이동한다.
- [ ] 로그아웃·탈퇴한 기기에는 더 이상 Push가 도착하지 않는다.
- [ ] 알림 거부 상태에서도 앱 내부 알림 피드는 정상이다.

## 7. 네트워크와 오류 복구

- [ ] Wi-Fi에서 이동통신으로 전환해도 진행 중 작업이 안전하다.
- [ ] 오프라인에서 오류 메시지와 재시도 동작이 명확하다.
- [ ] 느린 네트워크에서 중복 예약·중복 메시지가 생성되지 않는다.
- [ ] Worker 4xx·5xx 응답에서 무한 로딩이나 앱 종료가 발생하지 않는다.
- [ ] 이미지 실패가 화면 전체 실패로 이어지지 않는다.
- [ ] 재시도 후 최종 서버 상태와 앱 화면이 일치한다.
- [ ] 두 기기의 느린 전송과 고객/사장님 탈퇴·가게 연결 해제가 겹치면, 해제 완료 뒤 늦은 채팅이 새로 저장되지 않고 전송 실패가 표시된다. 기존 활성 예약 때문에 탈퇴가 거절되는 경우와 구분한다.
- [ ] 고객센터의 고객 탈퇴·운영자 권한 해제/마지막 담당자 소멸 뒤 늦은 문의는403/503으로 안내되고 메시지나 문의 상태가 바뀌지 않는다. 별도 로컬/스테이징의 대화 갱신 실패 후 재시도에는 메시지가1건만 남는다(운영에 실패 트리거를 넣지 않는다). 성공 응답 자체 유실의 멱등 보장과는 별도 검사다.

## 8. 접근성과 화면

- [ ] VoiceOver로 로그인부터 핵심 흐름을 진행할 수 있다.
- [ ] 큰 글자 크기에서 버튼과 주요 정보가 잘리지 않는다.
- [ ] 지원하는 가장 작은 iPhone 화면에서 주요 버튼에 접근할 수 있다.
- [ ] 라이트·다크 모드에서 글자와 배경 대비가 충분하다.
- [ ] 로딩·빈 상태·오류·승인 대기 상태를 사용자가 구분할 수 있다.
