# 맡겨멍 실제 기기·외부 서비스 수동 테스트 체크리스트

자동 smoke로 대체할 수 없는 항목만 모은 체크리스트다. 각 항목은 실제로 실행한 뒤에만 체크한다.

## 0. 실행 정보

- [ ] 테스트 대상 Git 커밋을 기록했다.
- [ ] 앱 버전과 빌드 번호를 기록했다.
- [ ] iPhone 모델, iOS 버전, Xcode 버전을 기록했다.
- [ ] 테스트 환경(개발/스테이징/운영 Worker와 D1)을 기록했다.
- [ ] 보호자·사장님·운영자 계정은 서로 다른 실제 계정으로 준비했다.
- [ ] 테스트 가게와 테스트 데이터가 실제 운영 데이터와 구분된다.

## 1. 설치와 앱 수명주기

- [ ] Release configuration을 실제 iPhone에 설치하고 첫 화면까지 실행된다.
- [ ] 앱 종료 후 재실행해도 인증 상태와 화면이 정상 복구된다.
- [ ] 백그라운드 전환 후 복귀해도 화면과 데이터가 정상이다.
- [ ] 앱을 강제 종료한 뒤 알림 또는 딥링크로 정상 진입한다.
- [ ] 이전 버전 위에 업데이트해도 Keychain과 사용자 데이터가 의도대로 유지된다.
- [ ] 삭제 후 재설치 시 남아야 할 정보와 삭제될 정보가 정책과 일치한다.

## 2. 실제 계정 인증

- [ ] 신규 카카오 계정으로 가입한다.
- [ ] 기존 카카오 계정으로 재로그인한다.
- [ ] 카카오 앱이 있는 경우와 없는 경우 모두 확인한다.
- [ ] 로그아웃 후 다른 계정으로 로그인했을 때 이전 계정 데이터가 보이지 않는다.
- [ ] 만료·폐기된 세션에서 로그인 화면으로 안전하게 돌아간다.
- [ ] Apple 로그인 신규 가입·재로그인·로그아웃을 확인한다.
- [ ] Apple 이메일 가리기와 이름 최초 1회 제공을 확인한다.
- [ ] 회원 탈퇴 후 기존 토큰으로 API를 사용할 수 없다.
- [ ] 두 기기에서 예약 신청과 고객/사장님 탈퇴가 겹칠 때, 예약 성공이면 탈퇴가 거절되거나 탈퇴 성공이면 새 예약이 거절된다. 기존 예약·프로필·사진이 절반만 지워지지 않는다.
- [ ] 다른 기기 탈퇴와 프로필 저장·강아지 등록이 겹쳐도 탈퇴 후 서버 개인정보가 다시 저장되지 않으며 실패 안내가 표시된다.

## 3. 권한과 외부 앱

- [ ] 지도 탐색과 핀 선택이 정상이며 앱이 위치 권한을 요청하지 않는다.
- [ ] 사진 권한 허용·제한·거부 상태에서 대체 흐름이 정상이다.
- [ ] 캘린더 권한 허용 후 일정 생성과 예약 취소 시 일정 삭제가 정상이다.
- [ ] 캘린더 권한 거부 시 예약 자체는 깨지지 않는다.
- [ ] 캘린더에 추가하지 않은 예약을 취소할 때 캘린더 권한 팝업이 나타나지 않는다.
- [ ] 추가한 일정의 권한을 설정에서 끄고 예약을 취소한 뒤, 권한 재허용·예약 내역 재조회로 해당 일정만 삭제되는지 확인한다(취소 내역 조회 가능한7일 내).
- [ ] 기기 시간대를 변경해도 시간권은 한국 예약 시각에 대응하는 시점이고, 종일 일정은 같은 날짜로 표시된다. 실제 일정의 시작·종료와 표시를 캘린더 앱에서 확인한다.
- [ ] 자정에 DST가 시작되는 기기 시간대의 종일 일정도 정상 생성된다. 실제 기기는 해당 지역의 향후 전환일을 테스트용 예약으로 준비한다. `America/Santiago`의2026-09-06은 자동 회귀 fixture이며 과거 날짜를 앱에서 새로 예약하라는 뜻이 아니다. 격리 날짜 검사가 실제 EventKit 표시를 대신하지 않는다.
- [ ] 알림 권한 허용·거부 후 앱 내부 알림 피드는 정상이다.
- [ ] 카카오맵 렌더링, 가게 위치 내부 지도창 열기·닫기, 전화 연결이 실제 기기에서 정상이다.

## 4. 보호자 전체 흐름

- [ ] 프로필을 조회하고 수정한다.
- [ ] 강아지를 등록·조회·삭제한다.
- [ ] 지도에서 업체를 탐색하고 필터를 사용한다.
- [ ] 일반 업체와 맡겨멍 파트너 상세의 기능 차이가 정확히 표시된다.
- [ ] 찜을 추가·해제한다.
- [ ] 파트너 업체에 문의하고 채팅을 송수신한다.
- [ ] 파트너 업체에 예약을 신청한다.
- [ ] 예약 내역을 조회하고 취소한다.
- [ ] 알림장을 확인하고 사진을 전체 화면으로 확인한다.
- [ ] 이용 완료 후 리뷰를 작성한다.
- [ ] 이용 이력이 없는 가게에는 리뷰를 작성할 수 없다.
- [ ] 같은 이용 건에 두 기기에서 리뷰를 제출하면 한 건만 저장되고 다른 화면은 재확인 안내를 표시한다. 작성 자격을 읽은 뒤 예약이 취소되거나 가게 연결이 종료돼도 새 인증 리뷰를 저장하지 않는다.
- [ ] 테스트 리뷰3개 중 시설 찬성1개는 홈 시설 필터에서 제외되고2개부터 포함된다. 짝수는 정확히 절반도 포함하며, 새로 집계 데이터를 읽은 상태에서 확인한다.

## 5. 사장님·운영자 전체 흐름

- [ ] 사장님 계정으로 가입하고 가게 등록을 요청한다.
- [ ] 승인 전에는 고객·예약·채팅·알림장에 접근할 수 없다.
- [ ] 운영자 계정에 등록 요청과 신청자 정보가 표시된다.
- [ ] 운영자가 실제 소유 증빙을 확인한 후 승인 또는 거절한다.
- [ ] 승인된 사장님에게 자기 가게만 표시된다.
- [ ] 자기 가게의 예약 요청만 수신하고 승인·취소할 수 있다.
- [ ] 고객과 채팅하고 알림장을 작성·수정·삭제한다.
- [ ] 다른 사장님 가게의 고객·예약·채팅·알림장에 접근할 수 없다.

## 6. APNs와 딥링크

- [ ] 새 예약 요청 Push가 사장님 기기에 한 번만 도착한다.
- [ ] 예약 승인·취소 Push가 보호자 기기에 한 번만 도착한다.
- [ ] 새 채팅과 새 알림장 Push가 대상 사용자에게만 도착한다.
- [ ] 포그라운드·백그라운드·강제 종료 상태에서 각각 수신한다.
- [ ] 알림을 누르면 정확한 예약·채팅·알림장 화면으로 이동한다.
- [ ] 로그아웃·탈퇴한 기기에는 더 이상 Push가 도착하지 않는다.
- [ ] 알림 거부 상태에서도 앱 내부 알림 피드는 정상이다.

## 7. 네트워크와 오류 복구

- [ ] Wi-Fi에서 이동통신으로 전환해도 진행 중 작업이 안전하다.
- [ ] 오프라인에서 오류 메시지와 재시도 동작이 명확하다.
- [ ] 느린 네트워크에서 중복 예약·중복 메시지가 생성되지 않는다.
- [ ] Worker 4xx·5xx 응답에서 무한 로딩이나 앱 종료가 발생하지 않는다.
- [ ] 이미지 실패가 화면 전체 실패로 이어지지 않는다.
- [ ] 재시도 후 최종 서버 상태와 앱 화면이 일치한다.
- [ ] 두 기기의 느린 전송과 고객/사장님 탈퇴·가게 연결 해제가 겹치면, 해제 완료 뒤 늦은 채팅이 새로 저장되지 않고 전송 실패가 표시된다. 기존 활성 예약 때문에 탈퇴가 거절되는 경우와 구분한다.
- [ ] 고객센터의 고객 탈퇴·운영자 권한 해제/마지막 담당자 소멸 뒤 늦은 문의는403/503으로 안내되고 메시지나 문의 상태가 바뀌지 않는다. 별도 로컬/스테이징의 대화 갱신 실패 후 재시도에는 메시지가1건만 남는다(운영에 실패 트리거를 넣지 않는다). 성공 응답 자체 유실의 멱등 보장과는 별도 검사다.

## 8. 접근성과 화면

- [ ] VoiceOver로 로그인부터 핵심 흐름을 진행할 수 있다.
- [ ] 큰 글자 크기에서 버튼과 주요 정보가 잘리지 않는다.
- [ ] 지원하는 가장 작은 iPhone 화면에서 주요 버튼에 접근할 수 있다.
- [ ] 라이트·다크 모드에서 글자와 배경 대비가 충분하다.
- [ ] 로딩·빈 상태·오류·승인 대기 상태를 사용자가 구분할 수 있다.

## 9. TestFlight 전 최종 확인

- [ ] 자동 smoke 결과가 PASS이고 결과 파일을 보관했다.
- [ ] Release 앱에 서버용 Secret, 개발자 메뉴, 테스트 계정이 없다.
- [ ] Privacy Manifest와 개인정보처리방침이 실제 동작과 일치한다.
- [ ] Critical과 Major 결함이 0건이다.
- [ ] 미실행 항목과 예외 승인 사유가 결과 문서에 남아 있다.
- [ ] 테스트한 커밋과 업로드할 Archive의 커밋이 같다.
